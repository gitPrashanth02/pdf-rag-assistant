# Page-Cited RAG

A local PDF question-answering app built with Streamlit. It parses uploaded PDFs with MinerU, splits extracted text into page-aware chunks, indexes embeddings in ChromaDB, combines semantic and lexical retrieval, reranks results, and generates document-grounded answers with page citations.

## Features

- Upload and ingest a PDF from the Streamlit sidebar.
- Extract page text with MinerU and retain page numbers on chunks.
- Embed chunks with `Qwen/Qwen3-Embedding-0.6B` and store them in ChromaDB.
- Combine vector and lexical search, then rerank candidate chunks with `BAAI/bge-reranker-base`.
- Generate answers with the local `Qwen/Qwen2.5-0.5B-Instruct` model.
- Include retrieved chunk and page numbers in the answer context and source list.

## Requirements

- Python and pip
- Internet access on first run to install dependencies and download model weights
- Sufficient disk space and memory for the PDF parser and language models; a compatible GPU can improve model performance

## Setup

From the repository folder, create and activate a virtual environment, then install the listed dependencies. The dependency file in this repository is currently named `requirments.txt`.

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirments.txt
```

### macOS or Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirments.txt
```

## Run the app

```bash
streamlit run app.py
```

Open the local URL printed by Streamlit. Choose a PDF in the sidebar and select **Upload and ingest**. When ingestion finishes, ask questions in the chat input. The first run may take longer while MinerU processes the PDF and model weights are downloaded.

Uploading a document again rebuilds the parsed text, chunks, and vector index. This is also necessary after changing the chunk format or metadata.

## Pipeline

1. `pdf_rag/parse_pdf.py` parses the PDF with MinerU and writes Markdown and JSON output.
2. `pdf_rag/chunking_markdown.py` reads MinerU's page data and writes page-tagged records to `chatgpt_chunks.jsonl`.
3. `pdf_rag/embedding.py` embeds the chunks and stores their text and metadata in `chroma_db/`.
4. `pdf_rag/retrival.py` combines vector and lexical search and reranks candidate chunks.
5. `pdf_rag/generation.py` builds the grounded prompt and generates the answer with page citations.

The Streamlit upload flow runs these steps through `pdf_rag/pipeline.py`. To use the standalone pipeline, place a PDF at `data/chatgpt.pdf` first:

```bash
python -m pdf_rag.pipeline --force
```

## Project files

- `app.py`: Streamlit user interface
- `pdf_rag/pipeline.py`: ingestion and query orchestration
- `pdf_rag/parse_pdf.py`: PDF parsing
- `pdf_rag/chunking_markdown.py`: page-aware text chunking
- `pdf_rag/embedding.py`: embedding and ChromaDB indexing
- `pdf_rag/retrival.py`: semantic and lexical retrieval with reranking
- `pdf_rag/generation.py`: answer generation
- `requirments.txt`: Python dependencies

Generated outputs include `chatgpt.md`, `chatgpt.json`, `chatgpt_chunks.jsonl`, and `chroma_db/`. The uploaded PDF is stored at `data/chatgpt.pdf` by the current app.

## Notes

- Page numbers are 1-based in chunk metadata and user-facing citations.
- Answers are generated by a language model, so verify important claims against the cited source pages.
- Do not commit private PDFs, generated indexes, model weights, or the local virtual environment to a public repository.
